# TreasureKeeper｜寶物庫整理助手

繁中服 Dalamud API 13 插件。按寶物庫分類瀏覽掉落，勾選物品全域自動丟棄，不限所在地。支援分類、搜尋、一鍵勾選、全域預覽、自動補錄庫內取得物品與手動補充。另有寶圖快捷欄解讀及自動確認。輸入 `/tkeep` 開啟整理助手，`/tkeep stop` 停止丟棄；`/tmap` 開啟地圖工具。

## 安裝（免自行編譯）

在 Dalamud 設定（`/xlsettings`）的「實驗性／Experimental」頁找到「自訂套件庫／Custom Plugin Repositories」，新增並啟用以下網址，再儲存設定：

```text
https://raw.githubusercontent.com/wenwen-ff14/TreasureKeeper/main/pluginmaster.json
```

開啟插件安裝器（`/xlplugins`），重新整理後搜尋 **TreasureKeeper｜寶物庫整理助手**，按「安裝」。目前提供繁中服 Dalamud API 13、版本 **0.1.9.0**；之後可從同一插件庫更新。

已編譯 ZIP 也可從 [GitHub Release](https://github.com/wenwen-ff14/TreasureKeeper/releases/tag/v0.1.9) 下載：[TreasureKeeper-0.1.9.0-api13.zip](https://github.com/wenwen-ff14/TreasureKeeper/releases/download/v0.1.9/TreasureKeeper-0.1.9.0-api13.zip)。手動載入時，將 ZIP 完整解壓至固定資料夾，再把 `TreasureKeeper.dll` 加入開發插件設定；一般安裝使用上方套件庫即可。

若先前已透過開發插件載入 TreasureKeeper，先停用該開發項目，再從套件庫安裝，避免重複載入；保留原本的插件設定檔。

## 使用

完整 G10 分庫、分類物品表見 [G10_ITEMS.md](docs/G10_ITEMS.md)，逐項 ID 與來源見 [g10-audit.json](docs/g10-audit.json)。0.1.9 已納入本次分享的神殿 53 種庫內取得紀錄，補足 19 項：14 種素材、4 種魔晶石及 1 種消耗品。神殿由 98 項增加到 117 項；其他來源清單維持原有項目。

1. 安裝後輸入 `/tkeep` 開啟整理助手；`/tmap` 開啟寶圖快捷解讀。
2. 在左側選擇掉落來源，勾選要「丟棄」的物品；未勾選的保留，設定自動儲存。同一物品在所有清單共用勾選狀態，從任一清單取消便全域保留。
3. 用分類、搜尋、背包持有或只看已勾選縮小列表，再按「勾選篩選結果」或「取消篩選勾選」。不設定篩選時，一鍵操作整個寶物庫。
4. 開啟「全域待丟棄預覽」核對背包，再按「啟動全域自動丟棄」。主城、野外、寶物庫及其他副本均會處理所有清單中已勾選的物品。正在瀏覽哪個寶物庫不會限制執行範圍，G10 外場也不需另行啟動。
5. 啟動後修改勾選直接生效；取消勾選會阻止後續請求，但已送出的請求仍可能完成。切換地圖與角色資料暫時未載入只暫停，保持啟用，載入後自動繼續。轉場前尚有請求時，先核對其結果；若仍未確認，結束舊請求追蹤後重新掃描目前背包，不沿用舊格子。

要在 G10 只保留深層地圖：分別選擇「運河寶物庫」及「運河寶物庫神殿」，清除篩選後按「勾選篩選結果」，再取消其他想保留的物品。ID **19770 深層傳送魔紋的地圖**永遠無法勾選，執行前也會再次排除。

0.1.2 首次載入會將舊版各庫勾選合併為一份全域清單，重複 ID 只算一次，並排除深層地圖、未知或無法丟棄的物品。升級後仍需手動啟動。新收錄的物品預設不勾選。

丟棄會移除一般背包 1～4 的**整疊物品，包含進場前已持有的同 ID 物品**，不只處理新增掉落。預設所有清單均未勾選、自動丟棄關閉；HQ 預設保留，可用上方開關納入。收藏品、染色／投影／鑲嵌與已有精煉度的裝備仍保留。水晶、貨幣、任務物品欄、兵裝庫、裝備欄、雇員與陸行鳥鞍囊不處理。

修改 HQ 設定會停止自動化；登入／重新載入後需手動啟動。戰鬥、轉場、過場、商店、交易與其他確認視窗會暫停。每次只送出一筆請求，等待背包數量更新；一般請求 8 秒未確認則停止，轉場中的舊請求則結束追蹤並重新掃描。停止或取消勾選不能撤回已送出的請求。

0.1.7 修正獨立魔晶石可能被裝備狀態誤擋：以本機物品表確認為魔晶石且無裝備欄位時，不套用精煉度、投影、染色、鑲嵌裝備的檢查，仍需勾選且通過一般背包、物品旗標等判斷。「全域待丟棄預覽」新增已勾選卻被保留的原因；執行記錄的 `[DiscardBlocked]` 也會指出物品 ID、背包格、旗標與原因。

## 自動補錄（0.1.5）

預設啟用，與自動丟棄分開。輸入 `/tkeep`，在「自動補錄」頁查看開關、狀態與所選寶物庫的取得紀錄。進入本機支援的寶物庫後，記錄自己一般背包與水晶的新取得物品；依當時所在的寶物庫加入清單並自動分類。已在公開清單的物品也會標記「庫內取得 · 已補錄」，留下首次及最近取得時間，重新載入後保留。物品清單可用「只看自動補錄」篩選，再批次勾選或取消。

0.1.8 起，每個寶物庫可在「自動補錄」頁的「本庫新補錄預設」各自選擇 **保留／自動丟棄**，初始全部保留。第一次補錄、且尚未有個別設定的物品會套用當時所在庫的預設，包含已在公開清單、但尚未實際補錄的物品。修改預設不回溯變更既有紀錄；下方每項的「目前設定」可直接切換保留或自動丟棄，與物品清單共用全域設定並立即儲存。

同一物品在不同庫仍共用一份全域選擇：首次補錄依該庫預設，跨庫再次取得沿用原選擇；個別或批次指定保留後，不會被之後的補錄改回丟棄。升級時沿用已有補錄、手動新增及全域勾選。舊版沒有記錄「尚未補錄的物品是否曾手動取消勾選」；若這類物品需要排除新預設，先在物品清單搜尋該物品，再按「取消篩選勾選」即可記住保留。

設定「自動丟棄」只會加入全域勾選，仍須按上方「啟動全域自動丟棄」才執行；補錄開啟且有本機支援的寶物庫設定自動丟棄時，即使暫無勾選，也可先啟動等待。啟用中收到新補錄物品會依現有規則處理一般背包的整疊，包含原有同 ID 物品；HQ 與物品狀態保護照常。深層地圖固定保留，水晶只記錄、不丟棄。

補錄不會自行啟動自動丟棄，也不會把進場前已有的物品整批加入。搬格、分堆、合併及同次通知中的跨容器移動不當作新取得，交易、製作及採集期間不補錄；切換角色、轉場與停用時重新建立基準。

此功能記錄「庫內取得」，不是伺服器完整掉落表，也不記錄其他隊員或未分配到自己背包的物品。一般野外區域無法單靠背包變化確定是 G10 寶箱獎勵，因此不自動歸入 G10 外場；外場仍可手動補充。進場或啟用後，要先等背包完整載入並顯示開始記錄，之後的新取得才會補錄。

0.1.6 降低反覆掃描、排序與暫存配置：背包完整快照只在補錄初始化時建立；一般丟棄掃描在未啟動且兩個視窗關閉時停止。清單索引、背包數量及補錄顯示按資料變化更新。新發現物品立即儲存，重複取得的時間更新合併為正常更新時每 2 秒一次，轉場、登出及卸載前補存；異常關閉可能遺失尚未寫入的最近取得時間。初始化失敗及卸載均會嘗試完整解除事件與 hook。

## 地圖快捷解讀（0.1.3）

1. 輸入 `/tmap`，或按整理助手上方的「地圖快捷解讀」。此功能與自動丟棄開關分開，預設啟用快捷解讀與自動確認。
2. 選擇一般快捷欄 1～10（12 格）或十字快捷欄 1～8（16 格），指定一個空格。
3. 在地圖旁按「放入空格」。已有內容的格子不會覆蓋；未持有的地圖也可先放好。沿用遊戲的共用／職業快捷欄設定，不寫入 PvP 快捷欄。
4. 地圖放在一般背包後，按一次該快捷鍵。插件開啟該物品的「解讀」，核對本次新出現的確認視窗與地圖名稱，再按「是」。也可在此頁直接按「解讀」，或用 `/tmap 17836` 解讀 G10。

清單直接讀取本機 `Item.FilterGroup = 18` 的寶圖，目前繁中客戶端可辨識 **25 種**，包含 G1～G17、深層及特殊地圖。日後客戶端新增符合該類別的寶圖可自動收錄；實際可用性仍由遊戲解鎖與解讀條件決定。深層地圖仍固定排除自動丟棄，但可由玩家主動按鍵解讀。

已有解讀中的寶圖、角色移動／戰鬥／忙碌、其他操作視窗開啟、丟棄請求未完成或背包未載入時，不開始解讀。每次按鍵只處理一張；重複按鍵不累積任務。0.1.7 起，卡住時再按同一快捷鍵或頁面的「重試」，可立即重新嘗試，不需等 8 秒，也沒有完成後的 1 秒冷卻。若本次確認框仍開啟，沿用並核對該視窗；若已解讀成功或背包數量改變，不再送出同一操作。角色仍在施法／忙碌時需等遊戲可操作，再按即可。

解讀期間暫停自動丟棄，並核對角色、區域、背包格及數量。無人再次按鍵時，8 秒仍未完成才清除追蹤；這只是舊請求的清理上限，不是重試等待時間。`/tmap stop` 或「取消本次操作」可停止尚未送出的步驟，已送出的解讀仍可能完成。

取消「自動確認本次解讀」後，仍會開啟解讀確認框，由你手動確認；其他用途的「是／否」視窗不會由此功能確認。可關閉「啟用快捷解讀」恢復遊戲原本的寶圖快捷鍵行為。

0.1.4 調整右鍵選單的處理時序：開啟後若已可用，立即選擇「解讀」，避免延至下一次更新時選單已關閉；尚未出現則繼續等待。超時訊息會指出等待右鍵選單、確認框、確認按鈕或遊戲結果等階段。Dalamud 記錄中的 `[MapDecipher]` 會記下版本、觸發來源及流程階段，方便對照實際問題。

## 建置與驗證

需要 .NET 9 SDK 及 API 13 的 Dalamud DLL。設定 `DALAMUD_HOME`，或指定 `-p:DalamudLibPath=...`；未指定時依序使用本專案 `.sdk/`、同層 `CrescentCompass/.sdk/` 或繁中啟動器的 `Dalamud/Injector/`。SDK 不包含於壓縮檔。

```powershell
./scripts/Validate.ps1 -Preview
./scripts/Package.ps1
```

`Package.ps1` 會產生已編譯安裝包、原始碼包與根目錄 `pluginmaster.json`，並核對 DLL 版本、API 13、安裝／更新連結及 ZIP 結構。發布時將安裝包上傳到對應版本的 GitHub Release，再更新 `pluginmaster.json`；公開下載驗證可執行 `./scripts/Verify-PluginRepository.ps1 -Online`。建置命令供開發者使用，一般玩家依上方「安裝」操作即可。

離線 UI 預覽需要同版 `cimgui.dll`，輸出在 `artifacts/ui-preview/`。清單建置工具只讀本機遊戲資料；不需啟動遊戲：

```powershell
./scripts/Fetch-CatalogSources.ps1
dotnet run --project tools/CatalogBuilder -c Release -- '<遊戲安裝目錄>/game/sqpack'
```

已完成 Release 編譯、2,361 項核心規則與資料檢查、離線 UI 排版與實際 ImGui 點擊測試，以及本機丟棄與 6 個地圖相關函式的特徵碼比對。2026-10-15，使用者在遊戲內確認 0.1.4 的寶圖快捷解讀與自動確認正常；本機記錄也確認 0.1.5 在神殿補錄自身取得物品並沿用全域勾選。0.1.7 已實際丟棄剛柔魔晶石肆型與器識魔晶石肆型各 3 個，並確認數量減少；轉場續行與立即重試通過離線驗證，尚待遊戲情境驗收。驗收項目及實測範圍見 `docs/IN_GAME_CHECKS.md`。

0.1.6 的離線效能比較使用相同測試程式及 0.1.5 原始碼：全域預覽每幀託管暫存配置由約 77,641 B 降到 1,289 B，補錄頁由 24,969 B 降到 120 B。結果不等於遊戲整體 RAM 或 FPS；方法、CPU 時間、保留記憶體波動與限制記錄在 [驗證報告](docs/IN_GAME_CHECKS.md)，原始量測保存在 `docs/performance-results.json`。

```powershell
dotnet run --project tools/UiPreview -c Release -- --performance artifacts/performance/current
```
