# 遊戲內驗收

離線測試與特徵碼相符不能取代遊戲內驗證。載入測試前，先停用其他插件針對同物品的自動丟棄／售出，避免同時處理造成結果無法判讀。

- 載入 API 13 DLL，輸入 `/tkeep`，確認 10 份庫內清單加 1 份 G10 外場清單、9 個本機支援寶物庫及固定保留深層地圖。初始沒有任何勾選。
- 在清單勾選一種可捨棄的素材，以「全域待丟棄預覽」核對 ID、背包位置及整疊數量。在主城啟動後也應處理該物品。
- 確認該疊消失、其餘物品不受影響，記錄顯示已送出及背包數量減少。確認隨後取得相同已勾選物品會接續處理。
- 在運河清單勾選與外場共用的牛鬼革，切換到外場時應同樣勾選；任一處取消後全域保留。啟動中修改勾選應立即生效，不需重新啟動。
- 確認主城、野外、其他副本及寶物庫都會處理全域勾選。0.1.7 起，轉場與角色物件短暫未載入均保持啟用；載入後繼續。請求期間轉場時，核對舊請求結果後重新掃描，不沿用舊格子；手動停止後不能因載入完成而自行啟動。
- 從 0.1.1 設定升級，核對各庫舊勾選的聯集，深層地圖仍排除；清空新清單後重新載入，不能重新帶回舊版勾選。
- 逐次記錄 G10 外場、運河、神殿、深層收到的物品 ID，與 `docs/g10-audit.json` 分區比對；尤其核對標示僅有 4.05 紀錄的 25 項，不能以離線來源檢查取代實際掉落驗證。
- 全選後確認深層地圖仍在，且不出現在待丟棄預覽。分類及搜尋後的一鍵勾選只影響目前結果。
- 確認 HQ 開關、收藏品與已加工裝備的保護符合預覽。打開其他確認視窗、進入戰鬥或過場時暫停。
- 在請求期間整理背包或發生拒絕提示時，確認不會連續重試；超時停止。不要把移動背包格子視為丟棄成功。
- 確認停止、修改 HQ 設定、登出／換角色及重新載入後的狀態。重新載入時保留全域勾選但不自動啟動。
- 在補充物品頁加入全新物品，確認只加入選定的來源清單且預設保留；若 ID 已在其他清單被勾選，則共用其勾選狀態。重新載入後仍在。

- 開啟 `/tkeep` 的「自動補錄」，確認預設啟用，且自動丟棄關閉時也能記錄。進入運河、神殿或深層後，狀態應顯示正確寶物庫正在記錄；記錄中可查到 `[LootDiscovery] Started` 及區域 ID。

- 取得已存在背包的素材、HQ、一般物品及水晶，確認同 ID 的數量增加會被辨識。只記錄自己的所得；其他隊員取得或尚在投骰的物品不應被視為自己已取得。
- 移動格子、整理背包、拆分／合併物品及卸下裝備，不應新增補錄項目。關閉功能期間取得物品，重新啟用後也不應倒算成新掉落。

- 同 ID 再次取得時不重複新增，最近時間會更新；重新載入仍保留紀錄、來源標記及既有勾選。轉到另一寶物庫後新增的物品只記入新庫。
- 離開寶物庫後停止補錄；主城、一般副本及 G10 外場區域的普通取得都不應混入庫內清單。

## 分庫補錄預設與逐項選擇（0.1.8）

- 運河設定新補錄預設「自動丟棄」，神殿設定「保留」；切換清單及重載後各庫仍保持各自設定。初次升級均預設保留。
- 在運河首次取得未補錄且未手動設定的物品，應加入全域丟棄；在神殿首次取得另一物品應保留。此規則也涵蓋公開清單已列出、但尚未補錄的物品。
- 在「自動補錄」逐項改成保留，之後重複取得、換庫取得及重載都不應再次選為丟棄；在「物品清單」更改同 ID 時，補錄頁同步更新。
- 修改本庫預設不回溯改寫既有紀錄。跨庫再次補錄同一物品時沿用既有全域選擇。升級前未補錄、也未手動新增的未勾選物品沒有舊版保留操作紀錄，需在物品清單搜尋該物品後按「取消篩選勾選」，以明確記住保留。
- 即使預設丟棄，深層地圖仍固定保留、水晶不可丟棄；HQ 與加工裝備的原有保護繼續有效。
- 停止全域丟棄時，新物品只補錄並依預設勾選，不應直接送出丟棄。補錄開啟且至少一個本機支援寶物庫預設丟棄時，可在無勾選狀態先啟動等待；停用補錄或僅設定外場／未支援區域時，不因此放行空清單啟動。

離線規則測試涵蓋以上優先順序、分庫設定與全域選擇的序列化還原，全部核心／資料檢查共 2,216 項。實際 ImGui 點擊驗證了兩個寶物庫分別設定、逐項保留／丟棄、全域同步及不可編輯的深層地圖／水晶；已檢視標準、窄視窗及大字體排版。以上新增流程仍待遊戲實際取得物品驗收。

同一離線效能程式量測新增下拉選單後的 142 筆補錄頁：每幀託管配置 120 B，三輪各 2,000 幀的 CPU 中位數 251.56 μs／幀，Gen0 次數均為 0；完整 GC 後保留量差為 0／0／+8,224 B。設定字典按寶物庫、決策集合按物品 ID 去重，不隨每次取得追加紀錄。這是短時間離線結果，不能據此判定先前遊戲 RAM 暴增已解決；原始資料在工作目錄 `artifacts/performance/v018/performance.json`。

- 0.1.4：一般背包視窗關閉與開啟時各測一次，分別以快捷鍵及滑鼠點圖示觸發。若出現超時，核對括號內階段及 Dalamud 的 `[MapDecipher]` 記錄；確認同次開啟選單即可選擇解讀，不依賴選單保留到下一幀。

- 測試至少一種特殊地圖；不同解鎖狀態由遊戲選單決定是否可解讀。未支援的選單／提示應停止並顯示原因，不點其他選項。
- 關閉快捷解讀、重新載入及卸載插件，確認 hook 釋放、原本物品使用正常；其他物品快捷鍵不受影響。

### 相同情境的離線比較

使用 .NET 9.0.20、x64、本機 API 13 cimgui。基準來自已交付的 0.1.5 原始碼 ZIP，隔離建置後使用與 0.1.6 相同的測試程式。每項先預熱至少 1,000 次且至少 1 秒，再量三輪；下表 CPU 是三輪每次耗時的中位數，配置量是每次操作的平均託管配置量。原始取樣、GC 次數、完整來源 SHA256 見 [performance-results.json](performance-results.json)。

UI 使用 1080 × 820 視窗、142 筆運河物品／補錄紀錄、140 格背包資料；含 ImGui NewFrame／Render，不含軟體圖片輸出、GPU、Dalamud 外層視窗、原生背包事件及設定寫入。每個 UI 情境每輪 2,000 幀。背包事件每輪 100,000 組新增／減少，重複清單合併每輪 20,000 次。

| 情境 | 0.1.5 配置 B／次 | 0.1.6 配置 B／次 | 配置減少 | CPU μs／次（舊 → 新） |
|---|---:|---:|---:|---:|
| 一組新增／減少事件 | 1,512 | 40 | 97.4% | 0.75 → 0.32 |
| 重複補錄合併同一 ID | 4,688 | 0 | 100% | 5.56 → 0.09 |
| 物品清單每幀 | 35,409 | 1,385 | 96.1% | 669.55 → 512.69 |
| 全域預覽每幀 | 77,641 | 1,289 | 98.3% | 295.49 → 232.56 |
| 自動補錄頁每幀 | 24,969 | 120 | 99.5% | 343.77 → 301.15 |

各情境新版三輪量測期間均未觸發 Gen0 GC。以全域預覽 60 FPS 換算，這個固定資料情境的託管配置流量約從 4.66 MB/s 降到 0.077 MB/s；這不是常駐 RAM 減少，也不是遊戲實際 FPS 改善比例。CPU 仍會隨機器負載、顯示資料量與 UI 狀態變動。

### 記憶體保留與限制

補錄基準只保留 158 格；執行記錄最多 60 筆。補錄歷史以寶物庫及物品 ID 去重，只更新首次／最近時間，不為每次取得無限追加物件。發現新的 ID 時清單與設定會正常增加，這是保留資料所需空間。快取會增加少量常駐資料，但不累積歷史快照；新增弱參考測試確認替換的背包快照可被 GC 回收。

事件壓力測試的三輪 GC 後保留量差為 0；清單合併為 -392／0／0 B。UI 的 GC 後保留量在 -8,744 至 +2,016 B 的單輪範圍內波動，部分輪次仍增加約 2 KB，原始數值完整保留。短測不能辨別這些小幅差異是否來自執行環境／綁定層，也不能排除長時間或原生記憶體問題；未將這些結果寫成「零洩漏」。

2,104 項規則／資料檢查包含快取失效、同物件清單新增、觀測時間排序更新、舊快照可回收、延後儲存上限、失敗保留與重試。離線 ImGui 點擊驗證確認分類、全域勾選、補錄篩選與地圖操作未因快取失去更新。初始化失敗的宿主清理路徑是程式碼審查，未在遊戲中故意觸發故障。

### 待完成的遊戲內確認

- 啟動 0.1.6 後，關閉兩個視窗且停止丟棄，再重新開啟；背包顯示應在下一次掃描更新，補錄與快捷解讀仍可運作。
- 取得新物品與重複物品，停留至少 2 秒後重新載入；確認新物品、最近時間、分類與勾選均保留。取得後立刻轉場或登出，也應補存。
- 同一場遊戲測試開關視窗、進出寶物庫與重載插件，觀察長時間記憶體曲線及 Dalamud 的插件耗時。全遊戲 RAM 也包含其他插件與資源，持續成長時需要進一步分析根物件／原生配置，不能只由總 RAM 歸因。
